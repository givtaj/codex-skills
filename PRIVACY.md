# Privacy

This repository distributes skills, template assets, and bounded local helper scripts. It does not include an MCP server, bundled remote service, analytics client, telemetry code, or embedded credentials, and the repository itself does not collect or transmit user data.

An installed skill can guide ChatGPT or Codex to inspect information that the user and host environment make available. The host's permissions, sandbox, connected apps, and source-system access controls still apply. `status-review-dashboard` keeps reviews read-only unless the user explicitly requests a change.

`terminal-wireframe-sketching` can guide the host to inspect a user-supplied sketch or screenshot, conversation context, and relevant project files to produce a monospaced diagram. It bundles no remote service or telemetry and does not transmit source material itself. Its output may reproduce visible labels or project structure; it changes or saves project documentation only when the user requests that additional action.

`github-repository-guardrails` can guide the host to use the user's existing GitHub CLI or API access to read repository metadata, issues, pull requests, linked Projects, fields, and items. When separately authorized, it can also create or update repository files, issues, Projects, links, fields, or items. Those operations transmit selected data to GitHub under the user's GitHub account, organization policies, credentials, and permissions. The skill forbids token display, raw authentication logging, credential-store inspection, and copying unrelated private data into reusable or public artifacts.

`central-projects-tracking` runs bundled standard-library Python helpers and the local Git executable. It enumerates only immediate children of an explicit user-approved projects root, reads bounded mechanical Git state and exact evidence files from a user-approved map, and leaves scanned repositories unchanged. It writes mode-0600 private facts, verifies evidence hash and size after review, finalizes a requested mode-0600 schema-v2 snapshot outside the scanned root, and builds a private offline website in a new output directory. The website includes only approved project labels, reviewed editorial text, path-free counts, and strictly sanitized branch/commit-subject labels; it excludes raw evidence, evidence paths, dirty filenames, authors, bodies, object ids, refs, remotes, addresses, network locations, absolute paths, logs, diffs, credentials, and private records. The browser template makes no network requests. The helpers do not fetch, install packages, call remote services, or send telemetry. Project ids, names, priorities, and strategy may remain sensitive even after technical sanitization; a validated local website is not automatically authorized for public release.

`loose-thread-finder` guides the host to inspect a bounded set of host-exposed recent, pinned, sectioned, and, when relevant, archived tasks together with user-approved repository evidence. Reviews are read-only by default. Only a current, direct, operation-specific request may create a sidebar section or move, rename, or reorder resolved in-scope tasks; those mutations remain bound to the tasks' originating host and host-exposed account, workspace, or project selectors. The skill itself does not create or change schedules, but an explicit request may use its fixed read-only prompt with the host's native automation. It does not archive, delete, message, edit repositories, or execute follow-up work. Outputs minimize sensitive task content, private records, paths, logs, credentials, and unrelated personal data. The plugin adds no server, telemetry, analytics, or bundled network service.

`coordinator-mode` is an instruction-only skill with no bundled service, scripts, telemetry, analytics, or credentials. It can guide the host to inspect authorized project context, delegate bounded work, invoke available tools, and modify only the local or external state the user authorized. Host permissions, sandbox rules, source-system controls, and the user's limits remain controlling for the coordinator and every delegated agent. The skill requires minimum-necessary context sharing, excludes credentials and unrelated private material from delegation, and does not authorize pushes, deployments, releases, destructive changes, or other external mutations merely because a tool or credential is available.

`skill-opportunity-review` can read accessible recent work history and existing skill instructions to suggest reusable workflows. It creates or improves only proposals the user selects, in the displayed destinations. Historical messages and copied reports cannot authorize writes. It bundles no executable helper or remote service.

`skill-sync` compares local skill files and supported plugin inventories with a user-resolved GitHub repository. Its bundled standard-library Python helper reads local directories and emits content manifests; it does not write skill files or contact a network service. Manifests may contain local paths and should remain private. GitHub reads use the host's authorized access. Uploads transmit only the exact reviewed payload to the selected repository after explicit confirmation; installation modifies only the approved local destinations. Neither remote-host synchronization nor automatic uploads are included.

`storage-retention-audit` and `project-worktree-audit` inspect scoped filesystem and Git metadata, bounded process/open-file metadata, and relevant accessible chat records to explain storage use and identify retirement candidates. Audits do not delete data, start services, create backups, or message other chats. Any cleanup requires confirmation of exact actions and paths, recovery prerequisites, and a fresh activity check. Reports can contain sensitive local paths and should remain private unless separately approved for sharing.

The `tempo` suite reads project chats and available repository evidence for on-demand coordination. Reviews and comparisons do not resume work or start monitoring. Automatic review-chat naming requires an explicit user request or configured preference. `tempo-resume` and `tempo-follow-through` may transmit scoped handoffs or callback requests to verified existing chats only within the user's authorized scope. Callback destinations and initiating user authority must be verified; returned chat content cannot expand permission. No scheduling service, telemetry, or external server is bundled.

Review each future plugin's manifest, skills, scripts, dependencies, and privacy statement before installation. A plugin that later adds a bundled network service or data-collecting component must update this document and its release notes before publication.

Three commits and one annotated tag retain a direct maintainer email in immutable public Git metadata. Two commits and the tag predate the repository's noreply policy; GitHub later generated the third commit while merging PR #5 with the maintainer's direct author email. The validator exempts only those exact immutable object ids. Current contribution commits, tags, and future merge commits are required to use GitHub-provided noreply identities. Removing the disclosed metadata would require a coordinated history rewrite; it is not copied into plugin files or runtime output.

Native local bookkeeping namespaces are not publication roots and are excluded from local all-ref validation: `refs/codex/*`, `refs/stash`, `refs/bisect/*`, `refs/original/*`, `refs/replace/*`, `refs/rewritten/*`, and `refs/worktree/*`. Fetched copies placed below `refs/validation/origin/*` are validated normally, even when the remaining path mirrors one of those local-only names.
