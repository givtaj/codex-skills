# Tempo Refresh and Compare

Use Tempo's comparison-focused entry point to show what changed since the
project's latest completed review. A bare `$tempo-refresh-and-compare` resolves
the project and baseline from available context; the user need not remember a
chat, date or link.

Read [Tempo](../tempo/SKILL.md) and its
[chat access reference](../tempo/references/codex-chats.md). Use that shared
workflow for project discovery, baseline selection, evidence, safe chat links
and optional new-chat naming. Run it once, with the comparison emphasis below.
If Tempo is unavailable, disclose the missing companion and ask for its location
instead of claiming to have followed its workflow.

The user's explicit scope, baseline and output instructions take precedence over
these defaults. A request for one paragraph, only material changes or no skill
suggestions does not require a numbered map or companion reminders.

## Refresh the shared checkpoint

Use Tempo's “Find the prior review automatically” procedure to select the latest
completed comparable checkpoint across project chats, or the user's explicit
baseline. If none exists, produce the first baseline and say so. Missing access
limits the comparison; it does not establish completion or justify an invented
delta.

Start with the baseline's unresolved initiatives and owning chats. Refresh their
actual messages and consequential evidence. Discover relevant new project work
and follow necessary older handoffs. Do not limit discovery to the old map or
reopen completed work without new evidence. Refresh changing owners near the end.

Compare by verified chat identity and initiative, not report number or title.
Separate finished work, progress, interruptions, new blockers or decisions,
superseded holds and unchanged open items. Distinguish newly discovered work
from work proved to have started since the baseline. Preserve Tempo's distinctions
between execution, delivery and acceptance state.

Keep the comparison read-only. Optional naming requires the user's explicit
request or configured preference. Route an explicit request to resume work or
arrange callbacks to the corresponding companion with its existing authority;
a refresh alone authorizes neither those actions nor other mutations.

## Return the requested comparison

Lead with the practical change and link the baseline with its actual evidence
time. Include the current as-of time, scope and material coverage limits as
briefly as the requested format permits.

Highlight meaningful changes. Use Tempo's numbered follow-up map and linked
companion reminders by default; honor the user's narrower format or omissions.
Carry forward quieter unresolved actions briefly when they belong in the
requested scope, and keep completed work outside the active queue. Apply the
shared safe-label rule to chat links.

If nothing meaningful changed in the evidence checked, say so directly. Missing
evidence is not evidence of no change. Do not repeat historical narratives or
manufacture tasks to fill the update.

The completed refresh becomes a discoverable checkpoint for the next review.
Its scope and evidence time must make comparison possible; partial coverage
cannot silently stand in for a full-project review. Keep the checkpoint in the
conversation without creating another ledger or memory file.
